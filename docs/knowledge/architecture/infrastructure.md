# Infrastructure & Dependencies

Alessandro's Blog is infrastructure-light: a static site on a CDN with no application servers and no databases. **Publish artifacts** (API JSON, static HTML, feed, sitemap) are regenerated by a small GitHub Actions workflow; PDF typesetting stays local.

---

## Hosting & DNS

| Layer | Provider | Notes |
|---|---|---|
| **Domain** | [EU.org / nic.eu.org](https://nic.eu.org) | Free, community-run domain registry operating since 1996. Aligns with the blog's open-web philosophy. TLD: `it.eu.org` |
| **Live URL** | `https://alessandrosblog.it.eu.org` | Primary public URL |
| **CDN / Proxy** | Cloudflare | Handles TLS, DDoS protection, caching, and privacy-friendly aggregate analytics (no cookies, no personal tracking) |
| **Origin** | GitHub Pages or equivalent static host | Serves static files (`index.html`, `api/`, `posts/`, `feed.xml`, `sitemap.xml`, `assets/`) |

## External Tool Dependencies

These tools must be installed on the host system to run build scripts. They are **not** managed by a Node package manager.

| Tool | Version | Required By | Installation |
|---|---|---|---|
| `pandoc` | Any recent | `build-pdfs.mjs` | `brew install pandoc` / OS package manager |
| `xelatex` | TeX Live / MacTeX | `build-pdfs.mjs` | `brew install --cask mactex` |
| `Node.js` | LTS (≥18) | All static generators | [nodejs.org](https://nodejs.org) |
| `Python` | ≥ 3.11 | `blogq` | Bundled with macOS or [python.org](https://python.org) |

> [!NOTE]
> PDF generation requires both `pandoc` (HTML → LaTeX) and `xelatex` (LaTeX → PDF). CI does **not** install TeX Live.

## Python Package Dependencies (`tools/blogq/`)

Managed via `pyproject.toml` using `setuptools`.

- Runtime: `jsonschema >= 4.26` — JSON Schema Draft 2020-12 validation
- Optional dev: `pytest >= 8` — unit tests in `tools/blogq/tests/`

Install with:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -e "tools/blogq[dev]"
```

---

## Automated Dependency Monitoring (Dependabot)

`.github/dependabot.yml` monitors the `blogq` Python package weekly:

```yaml
- package-ecosystem: "pip"
  directory: "/tools/blogq"
  schedule:
    interval: "weekly"
```

Node.js scripts have **no `package.json`** — they use only Node built-ins (`fs`, `path`, `child_process`, `crypto`).

## CI: Publish Artifacts

`.github/workflows/publish.yml` runs on push to `main` and `workflow_dispatch`:

1. Install and run `blogq check posts.json`
2. Run blogq unit tests (`pytest`)
3. `node scripts/build-static-api.js` (API + **BUILD_ID**)
4. `node scripts/build-static-pages.js`
5. `node tools/generate-feed.js`
6. `node tools/generate-sitemap.js`
7. Commit dirty artifacts with message `chore: regenerate static artifacts [skip ci]` (loop-safe)

**Out of CI:** `build-pdfs.mjs` (pandoc + TeX Live are too heavy for the default runner).

**Manual / local workflow for a new post:**

1. Add entry to `posts.json` (or compile a guest draft).
2. `blogq check posts.json`
3. Full pipeline: API → static pages → feed → sitemap (see [Build Pipelines](../workflows/build_pipelines.md)).
4. Optionally `node scripts/build-pdfs.mjs`.
5. Commit and push — CI re-validates and regenerates if needed.

## SEO & Crawling

`robots.txt` allows crawlers on the main site and blocks tools, submissions, and PDF mirrors. Primary crawl surface is **Static Post Pages** under `posts/`, listed in `sitemap.xml`, plus homepage JSON-LD and `feed.xml`. Details: [SEO Strategy](../workflows/seo.md).
